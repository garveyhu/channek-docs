# 打包与两条分发路

## 打包:用 `channek plugin pack`,别手工 zip

制品(`.ckplugin`)只能用官方打包命令打:

```bash
channek plugin pack <插件目录>
```

它按与**安装侧同一份**内容黑名单先把包剥干净(`.git*`、`.npmrc`、`node_modules`、编译缓存、疑似密钥文件)——而安装侧对这些是**整包拒**。手工 zip 出来的包能上架、能下载、指纹也对,最后卡在每个用户的机器上,你收不到任何信号;实测多数只因为夹带了一个 `.gitignore`。

**`node_modules` 不随包分发**:它按机器与平台装出来,打进去既臃肿又装不上。插件目录里带 `package.json` 依赖 + `package-lock.json` 即可——宿主会自动给用户一颗「就地安装依赖」的按钮(用 app 自带的 node、逐包校验完整性、不跑生命周期脚本)。T2 逻辑入口更推荐**全量 bundle 成单文件 CJS**,连这一步都省掉。

## 两条到达用户的路

**它们不是二选一,是同一个插件的两种到达方式。**

### ① 独立分发——插件是插件

用户拿到插件目录(下载 / 解压 / 商店安装),经「设置 → 第三方插件 → 导入」装到 `~/.channek/plugins/<id>/`。

- 适用:**通用能力**(一条 TTS、一个主题、一个查看器)——跟任何具体频道无关。
- 本地目录安装(含开发期 symlink)**不要求签名**;T2 另过安装前知情同意(按版本 + 摘要 + 权限清单批准,变了重新确认)。

### ② 随卡包捎带——插件跟着频道卡

导出 `.channel` 时,卡**依赖的**插件一并打进包里;收卡人导入卡包,插件被逐个送去过**同一条**信任门。

- 适用:**复刻一个频道**——卡说「我要这些能力」,包里就带着它们,收卡人解开即是完整一套。
- 谁被带上:卡 `requires.plugins`(含从步序反推的)∩ 本机已装 ∩ 非内置——只带卡要求的,不夹带你机器上装的其它东西。
- **签名闸**:离线侧载没有商店索引可比对,签名是唯一防篡改锚——包内 T1/T2 插件无有效签名一律拒装(T0 纯数据免签)。装不上的插件不牵连卡:卡是数据、先进库,失败逐条报告。
- **导入永不静默**:收卡人会看到「本包含 N 个可执行插件 · 最高信任级」的披露,逐个确认后才安装。

:::note 频道插件也走这条路
只给一个频道用的插件可以直接住进那个频道的文件夹(推荐 `plugins/<id>/`),由频道卡 `channel.json` 的 `plugins` 按相对路径点名。它是频道的文件:导出 `.channel` 时随做法一起进包,用 git 分享频道时随仓库走——不经插件目录安装。收卡人第一次打开频道时先过信任卡,信任之前一律不加载;T2 仍要逐个批准。见[信任分级](../concepts/trust-tiers.md)。等第二个频道也要用它,再把它做成独立分发的全局插件(见下一节)。
:::

## 频道插件提升成全局插件

第二个频道也要用某个频道插件时,别把插件目录再拷一份进去:两份代码会各改各的,同时开着时还会因为 id 相同互相拒载。用一条命令把它提升成全局插件:

```bash
# 在源频道目录里先预演:列出会搬哪个目录、改哪几张卡的哪几处,什么都不动
channek plugin promote acme.review-gate --also ../second-channel

# 确认无误,退出 Channek 后执行
channek plugin promote acme.review-gate --also ../second-channel --apply
```

它做三件事:

1. 把 `plugins/acme.review-gate/` 搬出频道,缺省放进本机插件目录 `~/.channek/plugins/acme.review-gate/`。想把源码放进自己的插件仓,加 `--into <目录>`:源码搬到 `<目录>/acme.review-gate/`,再从本机插件目录软链过去。**id 不变**:存储、设置、密钥注入都按 id 分。
2. 源频道的卡从 `plugins` 去掉那条路径,改在 `requires.plugins` 里按 id 写 `{ "id": "acme.review-gate" }`;`--also` 的每个频道(可写多次)也加上这一条。改卡走 app 自己的读写路径,任何一张卡改完不合格,命令在动手前就停下。
3. 搬完对插件和改过的卡各跑一遍 `channek check`,再列出剩下要在 app 里做的事:在插件管理里信任它(显示「待信任」时),在每个频道里启用它。

几种情况命令会拒绝,而且什么都不动:目标位置已经有东西、本机已经装着同 id 的插件、`--also` 的频道自己也带着一份同 id 的频道插件、`--into` 指到某个频道里面、插件清单不合格。Channek 开着时也拒绝执行,因为运行中的插件实例还指着旧目录。中途写失败会把改过的卡写回原文、把目录搬回去。

两边如果都是 git 仓库,各自提交:频道里少了插件目录,插件仓里多了它。

### 怎么选

| 你在做什么 | 走哪条 |
|---|---|
| 发布一个通用能力给所有人 | 独立分发 |
| 把自己的频道整套交给别人复刻 | 随卡包走(卡 + 频道插件 + 它依赖的全局插件) |
| 本地开发中 | `ln -s` 进发现目录 |

**卡不是插件的替代品**:能力做成插件、可复用;卡只是把它们用起来的那份描述。同一个插件既能独立发布,也能被任意多张卡带走——两条路指向同一份东西。

## 用到的官方 npm 包

全部 Apache-2.0,与 app 本体分开授权——你可以自由使用、修改、再分发这些接口层:

| 包 | 用它做什么 |
|---|---|
| `@channek/sandbox-sdk` | T1 沙箱桥(握手 / 白名单 op / 主题 / 存储),打进你的 bundle |
| `@channek/plugin-kit` | manifest 类型与 JSON Schema、校验 |
| `@channek/ipc-contract` | 桥应答的精确 DTO 类型(类型层依赖,运行时零依赖) |
| `@channek/style-card` | 按语义 id 解析卡与工件(写卡相关插件用) |
| `@channek/project-format` | `.channek` 工程格式类型(提议 EditTransaction 用) |
| `@channek/core` | 跨包共用的类型与纯函数 |
