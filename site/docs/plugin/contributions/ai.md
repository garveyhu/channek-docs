# AI 贡献

Channek 的 AI 层(Yan)自己不带创作域能力——它按卡声明的流程**编排插件贡献的能力**。AI 域开了四个贡献位:

| 点 | 一句话 | 状态 |
|---|---|---|
| `ai.tool` | LLM 可调用的读工具与低层写工具(写工具只产提案操作,不直接落盘) | 契约冻结中 |
| `ai.macro` | 高层意图宏:确定性算法批量产编辑操作,LLM 只给语义参数(如「删掉全部静音段」) | 契约冻结中 |
| `ai.analyzer` | 内容理解分析器(转写 / 静音 / 口头禅 / 镜头检测),产物按内容哈希落边车、可增量重算 | 契约冻结中 |
| `ai.delegate` | **受托执行**:声明「我能接活」,内核把整件事交给你的 agent 去干 | ✅ 声明面已开 |

## 现在就能做的两件事

**① 让 Yan 按得动你的命令。** Yan 与用户走同一条命令通道——你贡献的每条 [`ui.command`](./ui-basics.md) 都自动进它的工具目录。把 `description`(给模型读)与 `keywords`(用户会怎么说)写好,你的能力就是 AI 的能力,不需要等 `ai.tool` 开闸。

**② 让能力可被脱机编排。** 提供 `command` / `http` 形态的[能力](./capability.md),用户自己的 agent(任何 CLI 智能体)就能经 `channek cap` 问参数、`channek invoke` 调用你——`ai.delegate` 的世界观正是「内容制作的执行主体可以是内置 Yan,也可以是用户自己的 AI」。

## 写路径红线

:::warning 一切 AI 写操作走唯一写路径
无论工具还是宏,改剪辑工程只能产出**提案操作**进 `EditTransaction`——可预览、可撤销、可审计。任何绕过它直接改文档的设计不会通过审核。
:::

插件经命令 / rpc 触发的 AI 侧写入还有一条纪律:宿主分不清「用户在你界面上点的」与「你在后台自己调的」,所以插件调用写长期记忆这类接口时会落**待确认**状态,用户点头才生效——内置插件也走同一条路。

## 时间与产物纪律

分析器产物一律用有理时间(`{ value, rate }` 的整数对),不出现浮点秒;产物按内容哈希关联、带版本号,内容或算法变了才重算;**不进 `.channek` 工程文件**(工程只存创作事实,分析是可再生的派生数据)。
