# 环境与发现目录

一个 Channek 插件就是**一个文件夹**:里面有一份 `manifest.json`,加上它声明要用到的资源或代码。不需要注册中心账号,不需要构建服务——把文件夹放对地方,app 就能发现它。

## 插件放在哪

| 来源(scope) | 位置 | 允许的信任级 |
|---|---|---|
| 内置 `builtin` | 随 app 分发 | 全部 |
| 用户 `user` | `~/.channek/plugins/<插件id>/` | 全部(T1/T2 过各自信任门) |
| 频道 `workspace`(频道插件) | 频道文件夹里的目录,由频道卡 `channel.json` 的 `plugins` 按相对路径点名(推荐 `plugins/<插件id>/`) | 全部,但**频道被信任之前一律不加载**;T2 仍要逐个批准 |

`~/.channek/` 是用户插件资产根。目录名必须与 manifest 里的 `id` 一致。

:::note 为什么频道插件要先过信任门
频道文件夹可能来自网盘、git、别人发来的卡包——打开一个文件夹不等于同意执行里面的代码。所以频道插件守几道门:只认频道卡里点名的路径、不扫描;路径解析真实路径后必须仍在频道文件夹内;频道打开时先出一张信任卡,逐个列出插件的信任级和它能做什么,点「信任并加载」才加载;信任时记下代码指纹,代码变了就自动停用、要求重新确认;id 撞上已加载的插件即拒载。只有这个频道用的插件才放这里,多个频道都用的装到用户目录。
:::

## 开发期工作流

**软链是一等公民**:

```bash
ln -s ~/dev/acme.my-plugin ~/.channek/plugins/acme.my-plugin
```

然后在 app 里:**设置 → 第三方插件 → 重新扫描 → 启用**。

- manifest 与资源改动**自动热重载**(watch);没动静时点「重新扫描」。
- 插件目录顶层可以是 symlink(宿主对插件根做 realpath 后登记),但插件**内部**的 symlink 逃逸会被拒——所有资源必须真的落在插件目录内。
- **开发频道插件**:插件目录放进你自己的频道、在 `channel.json` 的 `plugins` 里点名,打开频道时在信任卡上勾「这是我自己的频道,打开开发模式」——之后改代码自动重新加载,不当成篡改。只给自己的频道开。

## 排错速查

| 症状 | 去哪看 |
|---|---|
| 插件没出现在列表 | 确认目录名 = manifest 的 `id`、`manifest.json` 是合法 JSON;再点「重新扫描」 |
| 红标 error | 点开看逐条校验错误(id 不合法 / T0 带了代码入口 / token 超白名单…) |
| 灰态 incompatible | `minAppVersion` 高于当前 app 版本 |
| 频道插件没加载 | 频道还没被信任(右上角「还差 N 件事」里有一条「待信任」,点「查看」打开信任卡);或频道被设成了「永不加载」(插件详情页或设置 › 本频道里「信任并加载」恢复);或 id 撞上了已加载的插件、路径不在频道内——频道里会出一条提示说明是哪个、为什么 |
| 灰态 unresolved | 缺少 `dependencies` 声明的插件,或它被停用了 |
| 行为不对 | 插件详情页「日志」区(每插件最近 200 条)+ 权限拒绝计数;报障点「复制诊断信息」 |
